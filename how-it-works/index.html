How it works

Three lines of HTML, and what they do

A versioned contract, a small loader, Shadow DOM isolation and an iframe fallback. No cookies, no third parties.

A versioned contract

The three lines you paste are a contract between your page and Regime Map: a <div> whose data-* attributes say what to show, a credit line in your own HTML, and one script tag. Everything lives under /embed/v1/, and inside v1 one rule holds: code that was pasted once keeps working. New options arrive as new attributes with defaults. data-product, which picks the product shown first, was added after launch; a map pasted on day one, without it, simply opens on online casino and still offers all five products.

A change that would break pasted code would ship under a new path, /embed/v2/, and v1 pages would keep their behaviour. If an embed is ever retired or switched off on a site, it shows a short card in its own frame. It never leaves a blank box and never redirects your page.

index.html
<div data-regimemap="map" data-lang="en" data-region="world" data-theme="light">Interactive map: gambling regulation by country.</div>
<p>Map: <a href="https://regimemap.com/gambling-regulation-map/">Regime Map</a></p>
<script async src="https://regimemap.com/embed/v1/embed.js" referrerpolicy="no-referrer"></script>

The no-JavaScript fallback

The sentence inside the <div> is what a reader sees when scripts are blocked, and what a crawler reads. With the credit line under it, it says what the embed is and where it comes from, so the page still makes sense without the map. The sentence is in the embed’s language, like the rest of the code: “Interaktive Karte: Glücksspielregulierung nach Ländern.” in German, for example. It carries no link of its own, because the credit line already links.

Loading without layout shift

Your page pays 2.6 KB up front: that is the whole loader, and it comes in with async, so rendering never waits for it. Before anything else, it sets aside the space each embed will take (regional proportions for a map, the typical card height for a card), and the paragraphs around it stay where they are. Nothing more downloads yet. The renderer and the data are requested once an embed is 200 px or less from the viewport, so a map placed at the end of a long article stays at 2.6 KB for readers who never get that far.

The loader finds out where it was loaded from by reading its own <script src>, so the same file works without configuration. It also understands common language variants: nb and nn give Norwegian, zh-TW and zh-HK give Traditional Chinese, and an unknown code falls back to English.

Several embeds on one page

Put five embeds on a page and you still get one loader and one copy of each file, because the maps and cards reuse the same requests. A duplicated script tag does no harm either: the extra copy just rescans the page. Loading stays lazy per embed, and each one starts when it nears the viewport.

Small on purpose

There is no framework behind them and nothing to install. The code is plain ES5 without dependencies, and it uses whatever system font the reader already has, so there are no font files either. Renderer files carry a content hash in their names and can be cached for a year; the loader is cached for an hour and points to the current renderer pair. Older renderers are kept online, so a page holding a stale loader still gets working files. Text lives in the per-language data file rather than in the renderer, which is why one cached renderer covers all 39 languages.

PieceGzipped
Loader2.6 KB
Map renderer, world geometry includedabout 41 KB
Map data, one language3.1–4.3 KB
Card rendererabout 5 KB
One country’s dataabout 1 KB

Together that is about 46 KB for a map and about 8 KB for a card. The country rows are compact: the code, the name, the dossier path and one letter per product, plus the labels of a lawful exception where there is one.

Shadow DOM isolation

In the script form, every embed lives in an open shadow root that starts from a blank slate: :host { all: initial; display: block }. From there the embed declares each property it needs on its own, including the font, line height, colours and box sizing. Theme CSS stays outside that boundary and the embed’s CSS stays inside. Our test page throws aggressive rules at div, a, table, svg, button and * to make sure of it.

The embed adds nothing to your page outside its shadow root. Not a style tag, not a link, not a wrapper.

Stylesheets without style attributes

Each shadow root adopts the embed’s CSS as a constructable stylesheet. Browsers without that feature get a <link> to the same stylesheet, placed inside the shadow root. You won’t find a single style="" attribute: dimensions, map colours and hatch patterns all go through the CSSOM, so the embed keeps working under a strict style-src policy, even with style-src-attr 'none'.

Every file is also plain ASCII, with non-ASCII characters written as escapes. A script without a declared charset is decoded in the host page’s encoding, and an early renderer that carried raw UTF-8 failed on pages in windows-1252 or Shift_JIS. The build now refuses to write any byte above 127, and the embeds are tested on pages declared UTF-8, windows-1252, Shift_JIS and nothing at all.

The iframe form

Some blog editors delete <script> tags from posts, so the configurator also has an <iframe> version. It loads the same embed from regimemap.com/embed/v1/frame/ and carries loading="lazy" and referrerpolicy="origin". The map frame is 16:10 with a 420 px floor. Why the floor? At 320 px wide, 16:10 gives you 200 px, and the tabs and legend don’t fit in that. Cards are trickier, because an iframe can’t grow with what’s inside it. So the configurator draws the card you picked, in your language, at 360 px wide, and writes the height it measured into the code. On a phone it fits. In a wide column you may see a strip of empty space below it; in a column narrower than 360 px the frame scrolls instead of cutting the card off.

Five products, zoom and search

The data carries all five statuses for every country, so switching product is a redraw, not a request. The product tabs are real tabs, one keyboard stop with the arrow keys between them, and where five don’t fit they become a menu that names the product shown. The title, the legend with its counts, the table view, the tooltips and the search all follow the product on screen. When a site sets data-product, that choice holds while the data loads, so readers never see online casino flash first.

Zoom is buttons and keys only: +, − and Reset, or the same keys while the map has focus, in steps of 1.6× up to 8×. There is no wheel listener and no pinch handling, so your page scrolls and zooms the way your readers expect. Small states are drawn as dots, spread apart with leader lines. A touch picks the nearest dot within 22 px, a 44 px target, while a mouse gets 10 px, because at 22 px the dots of Central Europe covered most of Germany. “Find a country” folds case and accents, including letters such as ł, ı, ø and ß, so “wlochy” finds Włochy.

The shapes come from Natural Earth at 1:50m, simplified so that neighbours share their borders exactly, in a Miller projection. Borders follow Ukraine’s position; for example, Crimea is shown as part of Ukraine. Northern Ireland is its own shape, because its rules differ from Great Britain’s.

39 languages

Every word an embed shows is in its data file, in that language: the tabs, the legend, the tooltips, the search, the dates and the card. Dates are written on the server, because a browser may lack date data for Georgian or Armenian. Joined phrases use each language’s own punctuation: French puts a space before the colon, and Japanese and Chinese use the full-width colon with no space after it.

The table view promises an alphabetical order, so rows are sorted with each language’s own collation rules on the server, and Japanese names by their kana reading. A browser’s built-in collation is no reference here: some browsers ship trimmed collation data without Albanian, Kazakh or Azerbaijani rules. The code you paste follows the language too. The configurator writes the fallback sentence, the iframe title and the first word of the credit line in the embed’s language; the link text stays “Regime Map”.

The credit-line check

The credit is a line you write yourself, outside the embed: an ordinary link in your HTML, and you’re free to add rel="nofollow". The embed checks its parent element and the two siblings after it for that link. It has to be visible to count. The wording is up to you and can be in any language.

No credit nearby? Then the embed draws a credit bar inside its own box. It will not insert links into your page, because widgets that plant links on other people’s sites are exactly what search engines treat as link spam. Links drawn by the embed open in a new tab and carry rel="nofollow noopener".

Privacy

  • No cookies, and nothing stored in the reader’s browser.
  • Nothing loaded from any other website.
  • Readers’ IP addresses are not logged.

Regime Map wants to know where its embeds appear, to credit real uses and to switch off spam sites, but not who reads them. After an embed renders, it sends one small notice: the page’s host and path, without query string or fragment, and whether the credit is present. It goes as a POST body rather than in a URL, so the page address never sits in an access log next to an IP address, and every request the embed makes says no-referrer. The notice is a claim, not proof: before a site is switched off, its page is fetched and checked for the embed and the credit.

A content delivery network can add a cookie on the way out, even when the embed sets none. The script form only loads JavaScript and JSON, which a CDN leaves alone. The iframe page is sent with no-transform, which tells the CDN to deliver it as it is, and both iframe forms, map and card, were checked in a clean browser profile from another site: no cookie, no extra request.

Content-Security-Policy

If your site sends a CSP, allow https://regimemap.com in these directives:

Content-Security-Policy
script-src  'self' https://regimemap.com;
connect-src 'self' https://regimemap.com;
style-src   'self' https://regimemap.com;
frame-src   https://regimemap.com;

script-src lets the loader and renderer run, connect-src lets them fetch the data and send the notice, and style-src covers the stylesheet fallback. frame-src is needed only for the iframe form. Because the embed never writes a style attribute, you don’t need 'unsafe-inline'.

Single-page apps

The loader scans the page once, when it runs. If your app adds an embed later, ask it to scan again. window.RegimeMapEmbed is the loader’s only global:

app.js
// after the new <div data-regimemap> is in the DOM
window.RegimeMapEmbed.scan();

An element is drawn once. To change its options, replace the element rather than editing its attributes.

React

In React, Next.js and similar frameworks, a small hook loads the script if it isn’t there yet and scans after every mount. This is a shortened version of the component in the examples repository, which also has the country card and the credit line in other languages:

RegimeMap.jsx
import { useEffect } from 'react';

const SRC = 'https://regimemap.com/embed/v1/embed.js';

// The loader scans the page once. In an app, scan again after every mount.
function useRegimeMapLoader(deps) {
  useEffect(() => {
    if (window.RegimeMapEmbed) { window.RegimeMapEmbed.scan(); return; }
    if (document.querySelector(`script[src="${SRC}"]`)) return; // still loading: it scans when it runs
    const s = document.createElement('script');
    s.async = true;
    s.src = SRC;
    s.referrerPolicy = 'no-referrer';
    document.head.appendChild(s);
  }, deps);
}

export function RegimeMap({ product = 'online_casino', lang = 'en', region = 'world', theme = 'light' }) {
  useRegimeMapLoader([product, lang, region, theme]);
  const extra = product !== 'online_casino' ? { 'data-product': product } : {};
  return (
    <>
      {/* a new key makes React replace the element when an option changes */}
      <div key={`${product}-${lang}-${region}-${theme}`} data-regimemap="map" {...extra}
           data-lang={lang} data-region={region} data-theme={theme}>
        Interactive map: gambling regulation by country.
      </div>
      <p>Map: <a href="https://regimemap.com/gambling-regulation-map/">Regime Map</a></p>
    </>
  );
}
